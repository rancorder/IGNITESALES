# Codex Retrieval Guide

## 目的

Codex が GitHub 上の案件ログを読み、必要な情報を取り出すための依頼文と探索順を定義する。

## 標準探索順

1. `AGENTS.md`
2. `docs/security-policy.md`
3. `docs/log-os-architecture.md`
4. `projects/<project_id>/README.md`
5. `projects/<project_id>/*.md`
6. `templates/*.md`

## Codex依頼テンプレート

### 案件ログの要約ではなく、次回判断材料にする

```text
このrepoのAGENTS.mdに従って、projects/<project_id>/ の直近ログを読んでください。
単なる要約ではなく、次回商談で確認すべき論点、仮説が当たった点・外れた点、
資料/台本/定例報告に反映すべき修正を抽出してください。
FACT / ANALYSIS / NEXT / JUDGMENT を分けて出してください。
```

### 定例報告化

```text
projects/<project_id>/ の今週ログから、定例報告用に以下の形式で作ってください。

■定性的な報告
■乖離している場合
原因：
改善：
対策：

外部共有できない内容は伏せて、内部メモとして残すべき内容は別枠にしてください。
```

### 商談者FB化

```text
対象ログをもとに商談者FBを作ってください。
責める文章ではなく、次回の問い・拾うべき反応・避けるべき説明過多を明確にしてください。
FACT と GPTの解釈を混ぜないでください。
```

### 顧客提示資料化

```text
対象ログを顧客提示レポートに変換してください。
内部事情・個人名・生ログ・仮説の断定を削除し、顧客が判断しやすい形に整理してください。
```

## grep / 検索キーワード例

- `JUDGMENT`
- `NEXT`
- `外れた仮説`
- `次回修正`
- `決裁構造`
- `温度感`
- `受付拒否`
- `本人拒否`
- `定性的な報告`
- `乖離`

## 取り出し時の注意

- 最新ログだけで断定しない。`summary.md` と過去ログも見る。
- 「顧客が言ったこと」と「べー/AIの読み」を分ける。
- 顧客提示用にする場合は、攻めた内部表現を丸める。
- 公開ビューアに出す場合は `public/log-os/data/` の JSON を更新する。
